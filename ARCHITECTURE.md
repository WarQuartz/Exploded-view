# Exploded View — Master Architecture and Product Contract
Version 1.0 | 2026-11-25 | Authoritative working specification
Owner approves material changes. Record decisions here before implementation. Never confuse planned and deployed features.

## Purpose
Know thyself. Disassembly required. Playful, intellectually challenging self-discovery, not a validated or clinical assessment. Deliver insights unavailable by rereading answers. Preserve autonomy, privacy, humor and interpretive uncertainty. Never diagnose, invent histories or infer sensitive identity traits; no high-stakes decision use.

## Product boundaries
Question Quartney is the umbrella; Exploded View is the discovery product; Control Room is private administration. Preserve the original Arena scenario game. Laboratory is installment-based. Compass (Ikigai), Collision (consensual comparisons), Mirror (reflection), Blueprint (strengths), Human Operating Manual (cross-installment synthesis) are planned. Ikigai explicitly deferred: inventory and preserve original questions, options, records and attempts before migration; no compulsory retakes.

## Deployed architecture
Public repository WarQuartz/Exploded-view contains source only. Never commit participant answers, dossiers, personal identifiers, credentials or tokens. Arena uses existing worker, static assets, Room Durable Object and scenarios.json. Laboratory is separate Cloudflare Worker exploded-view-lab, lab/worker.mjs, https://exploded-view-lab.courtneyhurt4.workers.dev/. Dedicated private D1 database holds submissions and dossiers separately; dossier primary key (submission_id, revision); latest revision delivered. Original answers retained independently. Local browser draft; server validation and duplicate protection; confirmed persistence before receipt. Public access exception applies only to Laboratory; Control Room stays protected. Results shell /results; GET /api/v1/results uses random UUID receipt as bearer capability; fragment link, no-store, no-referrer; possession allows viewing. This is not full account authentication. Manual AI generation through authenticated owner tooling; automatic analysis, admin UI, notifications, participant accounts and selective share cards not yet implemented. Browser/security tests written but not confirmed executed. Never imply deployment is end-to-end verification.

## Target contracts
Versioned catalog with stable question IDs, options, release state and dates. Submission has stable ID, installment/version, original answer payload, source (online/correspondence), consent and timestamp. Future participant identity separate from submission; no name-based merging. Dossier has revision, schema/policy version, provenance and review state. Append revisions; never replace original answers. Analysis jobs unique per submission/version/policy, pending/processing/ready/error, bounded retries and idempotent writes. Public API: GET /api/v1/installments, POST /api/v1/submissions; capability-protected GET /api/v1/results. No public listing or raw answers. Future separate revocable secret hashed at rest, scoped sharing, legacy link migration. Never log secrets or put them in URL queries. Group consent is not public-sharing consent. Correspondence entry requires permission.

## Mandatory dossier policy v1.0
Use answers as private analytical inputs. NEVER reproduce them, even as supporting evidence. No quotations, paraphrases of specific answers, question references, round recaps, inventories, or “you chose/said/answered” phrasing. No exact answer leakage in titles, roasts, prompts, metadata, fictional specs or share cards. Avoid generic recap disguised as analysis.
Write an integrated character study: infer plausible motivations, competing principles, tradeoffs, strengths and blind spots across all rounds. Explain potential real-life implications and alternatives; mark hypotheses, not established traits. Critique unfair or harmful implications without diagnosing or attributing dangerousness. Equal depth for everyone; no unrelated private history unless separately authorized. Do not invent evidence. Practical experiments must be low risk and voluntary. Humor targets patterns, never vulnerabilities or identities.
Standard sections: title, subtitle, core psychology, emotional architecture, intellectual architecture, moral paradox, relational implications, shadow pattern, growth frontier, personal experiment, questions for further exploration, personal motto, roast, warning label, disclaimer. Prefer coherent substantive paragraphs over labels and generic praise. No numerical personality scores without validated measurement. Original answers retained privately for authorized analysis only.
Quality gate: reviewer checks cross-answer synthesis, specificity, alternative interpretations, nonclinical language, actionable reflection, absence of raw-answer leakage and equal depth. Reject and revise if any fails. Keep earlier revisions private. This gate is a documented requirement, not an implemented automatic validator.

Admin dashboard and manual correspondence entry must remain private; comparisons only with consent. Human Operating Manual links installment insights and preserves revision history.
